# 客服回拨承诺管理系统（Callback Promise Manager）

客服无法当场处理咨询时，向客户承诺回拨时间并闭环跟踪的本地演示系统。
**纯 Python 标准库 + 原生前端，零第三方依赖**；电话、短信为模拟适配器，
录音仅生成本地虚构占位文本文件，所有时间线持久化在 SQLite。

## 一条命令启动

```bash
./start.sh                    # 首次自动注入含逾期样例的演示数据
# 或：python3 -m callback --reset
```

打开 <http://127.0.0.1:8000> 。

- `RESET=1 ./start.sh`：重置数据库重新注入样例
- `PORT=8080 ./start.sh`：指定端口
- `python3 -m callback --help`：全部参数

数据库与虚构录音位于 `callback/data/`（已 gitignore）。

## 功能对照

| 需求 | 实现 |
| --- | --- |
| 承诺回拨时间，记录问题摘要、可接听时段、负责坐席、原始会话 | 建承诺四要素必填；客户按星期维护 `ok`/`dnc` 时段（支持跨午夜、时区） |
| 回拨完成填写结果与下一步 | `complete` 两者必填，未完成承诺可一键模拟拨打 |
| 不接通有依据再次预约 | `reschedule` 必填依据；以"不接通"为由须先有 `no_answer/refused` 拨打记录 |
| 承诺时间不能落在禁扰时段 | 建单与改约均校验；禁扰优先于可接听窗口，左闭右开，支持跨午夜窗口延续到次日 |
| 坐席请假未完成承诺转交值班组 | `handover_leave_to_duty` 批量交接并写 `leave_handover` 责任链 |
| 号码拨错 / 客户拒接 / 他渠道解决 / 独立处理重复创建 | 四种取消状态分别要求相应证据（wrong_number/refused 须先拨测、他渠道须填渠道、重复须指向保留单） |
| 超过承诺时限 | 承诺时刻 + 30 分钟宽限为时限；`sweep_overdue` 判逾期并追加只增时间线 |
| 坐席不能删除逾期记录，主管确认后关闭争议 | 逾期/争议记录对任何角色不可删除；仅主管可 `close_dispute`（须填确认说明） |
| 并发转派不产生两个有效负责人 | `owner_version` 乐观锁：并发时一个成功、一个收 409 冲突，需刷新版本重试 |
| 提供承诺队列 / 客户时段 / 拨打记录 / 转派与失约报表 | `/api/state`、`/api/customer/{id}`、`/api/report`；右侧报表三页签 |
| SQLite 保存时间线 | `events` 表只追加；另有 `ownership_log` 责任交接流水 |
| 录音只用本地虚构文件；电话/短信模拟 | `adapters.py`：`PhoneAdapter`（生成占位 txt）、`SmsAdapter`（只写库不外发） |
| 单命令启动并含逾期样例 | `seed.py` 相对真实启动时间构造数据，任意时刻启动都有逾期、倒计时、请假交接样例 |
| 坐席界面按承诺时刻排序并显示倒计时；客户历史与当前承诺同屏 | 左队列（每秒本地刷新倒计时、<15 分钟琥珀、逾期红）；中详情含同屏客户历史 |
| 主管视图突出失约原因和责任交接 | 右栏"转派与失约"：红/紫卡片展示失约原因、超时时长、当前责任人、交接链 |
| 白、墨灰、少量琥珀色 | `web/styles.css`：白底 + 墨灰顶栏/文字 + 琥珀主色 |

## 界面操作

- **视角切换**：右上角"坐席 / 主管"。坐席视角只看自己名下承诺；主管看全部并可关闭争议。
- **新承诺**：选择客户与承诺时刻，系统拒绝禁扰时段并拦截重复创建。
- **承诺详情**：模拟拨打（接通/未接/拒接/拨错）→ 回填完成、有依据改约、取消（四类原因）、转派、发短信。
- **倒计时**：承诺时刻前倒计时；进入宽限期红色提示；扫描后变"已逾期"。
- **主管**：右栏失约卡片点"主管关闭争议"；任何"删除记录"对逾期单都会被拒绝。

## 运行测试

```bash
python3 -m unittest discover -s callback/tests -t .
```

覆盖：**禁扰规则**（边界、跨午夜延续次日、时区换算、禁扰优先）、**逾期判定**
（宽限前后、扫描幂等、时间线事件、逾期不可回填）、**转派竞争**（多线程同时
转派恰一个生效、版本重试、非负责人拒绝、请假批量交接）、**主管权限**（逾期
不可删、仅主管关争议、有拨打记录不可删）、业务流程与 HTTP API（含跨线程并发
转派 200/409）。

## 项目结构

```
callback/
├── __main__.py        # python -m callback 入口
├── server.py          # http.server JSON API + 静态托管
├── service.py         # 核心业务规则（禁扰/状态机/转派乐观锁/权限）
├── db.py              # SQLite schema 与只增事件表
├── adapters.py        # 模拟电话（虚构录音）/ 模拟短信
├── reports.py         # 队列/时段/拨打/转派失约报表
├── seed.py            # 含逾期样例的种子数据
├── web/               # index.html / app.js / styles.css（无框架）
└── tests/             # 53 个 unittest 用例
```

## 关键设计

- **时间**：统一存 UTC ISO-8601；禁扰判定换算为客户本地墙上时钟（`tz_offset` 分钟），
  窗口按星期定义、跨午夜自动延续到次日。
- **时限与逾期**：`deadline_at = promised_at + 30 分钟`，扫描器只动 `pending` 单，
  逾期写 `expired` 事件，不删除任何数据。
- **并发转派**：`UPDATE ... WHERE owner_version=?` 原子比较，配合 SQLite
  `BEGIN IMMEDIATE` 写事务，落败方收到 `OwnershipConflict`（HTTP 409）。
- **审计**：`events` 只追加；有拨打记录的承诺连主管也不能物理删除。
- **模拟边界**：没有任何真实通信代码；录音文件为带说明的 `.txt` 占位。
